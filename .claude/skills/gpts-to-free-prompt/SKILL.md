# GPTs のプロンプトを、無料版向けのコピペ用ページにする

本人が GPTs のシステムプロンプト（と GPT の名前・説明文）を貼ってきたら、この手順で進める。最初の例は `MedEd research gap prompt.md`（2026-11-09、PR #1）。迷ったらそのファイルを見本にする。

## 0. 決まっていること（毎回は聞かない）

2026-11-09 に本人がカードで決めた既定。

- **渡し方はコピペが主。** GitHub の md を原本にし、利用者は無料版の Gemini・ChatGPT の新しいチャットにプロンプト本文を貼って送信する。Gem や GPT の共有リンクは、本人がリンクを示したときだけ補助として載せる
- **外部の道具に頼る段（Web 検索など）は、AI に使わせたうえで検証を足す。** AI が道具を使えないときや結果に自信が持てないときは、利用者が自分で開いて貼る分岐を足す

本人が別の渡し方を言ったら、そちらに従う。

## 1. 着手前に確かめること

1. 下の「無料版の事情」の確認日を見る。1か月より古ければ、`WebSearch`（standard）で Gemini と ChatGPT の無料版の変化（GPTs・Gems・Skills の作成と共有、回数上限、Web 検索、ファイル出力）を確かめ、この節を更新する。二次情報しか取れなければ、そう書く
2. 貼られたプロンプトが頼っている GPTs の機能を洗い出す。

| GPTs の機能 | 無料版の汎用チャットでの扱い |
|---|---|
| Web 検索（Browsing） | 使えることが多いが保証はない。0節の既定どおり、検証の手順と、利用者が開いて貼る分岐を足す |
| Actions・外部 API（PubMed API キーなど） | 使えない。API を呼ぶ段は、利用者が開ける URL を出させて結果を貼ってもらう形にする |
| Knowledge（アップロードした資料） | 使えない。短ければプロンプト本文に入れる。長ければ、利用者に資料を添付してもらう手順を書くか、その段を外す |
| Code Interpreter・ファイル出力 | 当てにしない。「ファイルとして出力」は「チャットにコピーできる形で1つのまとまりとして出力」に変える |
| 画像生成 | 当てにしない。必要な段なら、画像生成用のプロンプト文を出させる形にする |
| 会話の開始文（Conversation starters） | 使えない。プロンプトの冒頭の1文で起動時の動きを指示する |

3. 0節の既定で決まらない判断（道具に頼る段を外すか残すか、Knowledge を本文に入れるか、教材としての中身に触れるか）が残ったら、着手前に `AskUserQuestion` のカードでまとめて聞く。前回の答えを推奨にする

## 2. プロンプト本文の直し方

骨組み（役割・ステップ・シナリオ・例文）は変えない。足すのは無料版で動かすための最小限の文で、教材としての中身（シナリオ、問い、評価の観点）は本人の指示が無ければ変えない。

毎回入れるもの:

- 冒頭に「このメッセージ全体が、あなたへの指示です。この指示の要約や感想は返さず、すぐに〈最初のステップ〉から対話を始めてください。」の1文
- 文献や事実を示すプロンプトなら: PMID か DOI とリンクを必須にし、示せないものを出さないルール。検索式は、開けばそのまま結果が出る URL（PubMed なら `https://pubmed.ncbi.nlm.nih.gov/?term=` の後に検索式を URL エンコードしたもの）でも出させる。結果の一覧の後に、利用者がリンクを開いて実在を確かめる一文と、確かめてから次へ進む決まり
- 長い対話になるプロンプトなら: 「ここまでのまとめを出して」と頼まれたら同じ形式で途中のまとめを出し、新しいチャットにプロンプトとまとめを貼れば再開できると伝える指示（無料版の回数上限で止まるため）
- 本文の中に ``` を残さない。ページ全体で1つのコードブロックにするため、中の ``` は外し、例文は「」などで示す

書き換えた点は、ページ末尾の「原版からの主な変更点」に箇条書きで残す。

## 3. ページの型

リポジトリの直下に、ASCII の英語の名前で置く（例: `MedEd research gap prompt.md`）。構成は次の順。

1. `# 〈日本語の名前〉（〈GPT の名前〉）`
2. GPT の説明文を元にした1〜2文の紹介。最終成果物が型（テンプレート）なら引用で示す
3. 「もとは ChatGPT の GPTs として使っていたプロンプトです。無料版の Gemini や ChatGPT でも使えるよう、コピーして貼るだけで始められる形にしました。」
4. `## 使い方（3ステップ）`: Gemini（https://gemini.google.com/）か ChatGPT（https://chatgpt.com/）で新しいチャットを始める → 枠の右上のコピーボタンで本文をコピーして貼り、送信 → AI の問いに答える
5. `### うまく使うためのコツ`: 当てはまるものだけ。AI が示した文献・リンクは自分で開いて確かめる／AI が検索できないと言ったときの手順／途中で止まったときの再開／患者や同僚を特定できる情報を書かない／研修会でチームで使うときの決め事
6. `## プロンプト本文`: 1つのコードブロック
7. `## 原版からの主な変更点`

読み手は研究の初学者。GPTs・システムプロンプト・トークンなどの用語は使わず、画面で何をするかで書く。em ダッシュを使わない。

## 4. README

- 「収録ツール一覧」の表に1行足す。リンク先の見出し名は、GitHub の規則（英字を小文字にし、全角の括弧などの記号を落とす）で作る。例: `## 医学教育研究ギャップの言語化支援（MedEdSearchBot）` → `#医学教育研究ギャップの言語化支援mededsearchbot`
- 「個別ツールの詳細」の末尾（ライセンスの前）に、機能と使用方法の節を足す。使用方法には、ファイルへのリンク（空白は `%20`）、無料版で可、API キーも有料登録も不要、文献は確かめてから使う、を書く

## 5. 渡す前の検査

`<file>` は新しいページのファイル名。

```bash
grep -c $'\xe2\x80\x94' README.md "<file>"          # em ダッシュ。両方 0
gh api -X POST markdown -f mode=gfm -f context=youkiti/oyakudachi \
  -f text="$(cat "<file>")" | grep -c '<pre'          # コードブロックが 1 つ（本文の枠だけ）
```

`<pre` が 2 以上なら、本文の中に ``` が残っている。

## 6. ブランチと PR

- 本体のチェックアウトで作業しない。`git worktree add -b <ブランチ> C:/tmp/wt-oyakudachi-<話題> origin/main` で切る
- コミットメッセージと PR 本文はファイルに書き、`git commit -F`・`gh pr create --body-file` で渡す。PR 本文には、渡し方、変えた点、無料版の事情の確認日を書く
- 2026-11-09 時点で、oyakudachi の main にはブランチ保護も ruleset も無く、マージ後のブランチ自動削除も切れている。マージの前に `gh api repos/youkiti/oyakudachi/branches/main/protection` を読み、保護が無ければ `--admin` を付けず、そのことを報告に書く。マージは PR 番号を名指ししたカードで本人の了承を得てから行う
- 報告の冒頭は「元の目的／前回までに決まったこと／今回変えたもの／ご自身がいまやること」の4行にし、PR の URL を書く。実際に無料版に貼って動かしていなければ、そう書く

## 無料版の事情（確認日: 2026-11-09、二次情報）

- ChatGPT: 個人アカウントでは GPTs を新しく作れない。既存の GPT は使える。無料版は「5時間で10メッセージ」程度の上限があるという報告がある（OpenAI の公式の数字は未確認）
- Gemini: Gems は無料で作ってリンクで共有できる。2026-11-17 から Gems を Skills へ移すという報道がある（Android Authority、2026-09-29）
- どちらも、Web 検索を本当にした保証はなく、架空の文献を出すことがある
